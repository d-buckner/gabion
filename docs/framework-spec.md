# Framework Spec (working title: TBD)

Status: DRAFT v0 — decisions marked [OPEN] need sign-off.
Inspired by Dune (xAI Grok Bot client architecture): agents take shortcuts, so the
shortest path must be the correct path. Enforcement is mechanical (crate graph,
compile targets, lint gates), never a standard the author has to remember.

## 1. Goal

Build single-binary Rust apps where the same business logic runs:

1. natively (CLI + native renderer),
2. in the browser as wasm (renderer + in-process core),
3. on a server (HTTP API + MCP),

with zero duplication of business logic. Every service operation is automatically
available as a CLI subcommand, an HTTP endpoint, an MCP tool, and a typed client
call — generated from one definition.

## 2. Non-goals (v1)

- Not a UI framework. The renderer is pluggable; Dioxus is the recommended default
  (only mature native+wasm UI stack). [OPEN: confirm renderer-agnostic vs bundled]
- No streaming/SSE surfaces in v1 (contract shape reserved for it).
- No mobile targets.
- Not a web framework replacement: axum/rmcp/clap are used internally, not rebuilt.

## 3. The load-bearing decision (DECIDED: Option B)

The service core is **pure and target-agnostic**. It compiles for
`wasm32-unknown-unknown` and native. No tokio, no std::fs/net/time/thread inside
core. All effects (clock, storage, network, sleep, randomness) are capability
traits with per-target implementations supplied by the host.

Consequence: the compile target itself is the strongest lint. A service fn that
reaches for `std::fs` compiles natively and **fails on wasm** — the shortcut is
mechanically sealed, not reviewed.

## 4. Layout: feature-first, sealed per feature (Dune colocation, Rust enforcement)

Two orthogonal walls, both enforced by the crate graph (not lints):

- **Process wall** (Dune: main vs renderer): render <-> core. Render may only
  import the feature's `api` crate.
- **Feature wall** (Dune: feature colocation + cross-feature import ban):
  feature A may import feature B's `api` only — never B's `core` or `render`.

```
myapp/
├── Cargo.toml                          # workspace (members generated by `gabion feature add`)
├── platform/                           # framework runtime + app-wide shared code
│   ├── gabion/  gabion-macros/  gabion-cli/      # (see §9)
│   └── myapp-shared/                   # cross-cutting types: Id<T>, Money, Page<T>, AppError
├── features/
│   └── todo/                           # EVERYTHING about todo lives here — one folder
│       ├── todo-api/                   # wire types + #[service] trait (compiles everywhere)
│       ├── todo-core/                  # impl of the trait; pure; depends: todo-api, shared, gabion
│       └── todo-render/                # UI components; depends: todo-api, shared, gabion, ui kit
└── hosts/
    ├── myapp-host-native/              # bin: CLI + native renderer (in-process cores)
    ├── myapp-host-server/              # bin: axum + MCP + serves wasm bundle
    └── myapp-host-web/                 # cdylib: wasm renderer + HTTP client
```

### Why 3 crates per feature instead of 3 modules

Cargo.toml dependencies ARE the import ban: a crate can only `use` what's in its
`[dependencies]`. With module-per-feature you'd need arch-lint to police
`use crate::todo::core::...` from render code; with crate-per-feature the import
is unrepresentable. `gabion feature add todo` generates the boilerplate, so the
colocation cost is zero for humans and agents. Compile time is fine: api crates
are types-only and fast; cargo parallelizes small crates.

### Allowed edges (gabion check audits every Cargo.toml against this table)

| Crate            | May depend on                          |
|------------------|----------------------------------------|
| X-api            | gabion, shared, other features' *-api      |
| X-core           | X-api, shared, other features' *-api   |
| X-render         | X-api, shared, ui kit — NOT any *-core |
| hosts            | all *-core + *-render (composition only)|
| shared           | gabion only — never any feature            |

Cross-feature calls: todo-core may depend on billing-api and receive billing's
client (in-proc or HTTP) — never billing's internals. This is Dune's "features
talk through their public surface" rule, made physical.

### Registration without wiring (shortest path = correct path)

`#[service]` registers each impl via `linkme` distributed-slice; hosts
auto-collect routes/tools/subcommands with zero manual registration. An agent
adds a feature folder and it appears in all four surfaces. `gabion check` verifies
the Cargo.toml edge table, so hand-added forbidden deps (the agent "shortcut")
fail CI with a message naming the wall rule violated.

DTOs live in `*-api`, not `*-core`. If an agent puts a DTO in core, render gets
an immediate compile error pointing at the wall — the error message is the
documentation.

## 5. The contract: one trait, four surfaces

```rust
// features/todo/todo-api/src/lib.rs
use gabion::prelude::*;

#[derive(Serialize, Deserialize, JsonSchema)]
pub struct CreateTodo { pub title: String }

#[derive(GabionError)]            // one error enum -> HTTP status, MCP error, CLI exit code
pub enum TodoError { #[code(404)] NotFound }

#[service]                   // generates client, router, clap, mcp, openapi
pub trait TodoService {                 // the trait IS the boundary:
    async fn create(&self, input: CreateTodo) -> Result<Todo, TodoError>;
    async fn list(&self, q: ListQuery) -> Result<Vec<Todo>, TodoError>;
}

// DECIDED: no per-method surface attributes. Every method in a #[service] trait
// is generated into every surface. An op that must not be remote lives outside
// the trait — a plain trait here for cross-feature in-proc calls:
pub trait TodoInternals {
    async fn recompute_stats(&self) -> ();
}
// ...or an inherent method on the impl in todo-core, reachable by nothing
// outside the feature. Adapters hold Arc<dyn TodoService>, so neither is
// reachable from any surface. Structure, not lint.
```

Because there is no attribute to review, the reviewable artifact is the *set* of
reachable operations: `gabion check` locks it in `.gabion/surfaces.lock` and
fails when it drifts, so "this method is now callable by an agent" appears as a
diff in the PR rather than in production.

`#[service]` generates, feature-gated so each host compiles only what it needs:

| Feature    | Generated artifact                          | Used by        |
|------------|---------------------------------------------|----------------|
| (default)  | wire types + `TodoServiceClient` trait + `Http` impl (fetch-based, wasm-safe) | render, web |
| `inproc`   | `InProcess` client impl (direct call, zero serialization) | native host |
| `server`   | axum routes + OpenAPI 3.1 doc               | server host    |
| `mcp`      | rmcp tool definitions (schemas from JsonSchema) | server host  |
| `cli`      | clap subcommand mapping                     | native host    |

The renderer calls `client.create(input)`. On native that's an in-process call;
on web it's a POST to the server. Same signature, same types, same errors.
This is the Dioxus `#[server]` dual-codegen pattern, generalized to four
surfaces and enforced by the crate wall.

Wire format: JSON, one POST per method (`POST /api/todo.create`), args as body,
`Result<T, E>` envelope. OpenAPI exported from the same source for public API
docs and external codegen. [OPEN: CBOR/MessagePack as option for wasm payload size]

## 6. Capabilities (effects)

```rust
// crates/gabion/src/caps.rs — what exists today
pub trait Caps: Clone + Send + Sync + 'static {
    type Clock: Clock;    // fn now(&self) -> Timestamp (whole seconds, on purpose)
    type Store: Store;    // async key-value of JSON strings
    type Random: Random;  // fn next_u64(&self) -> u64; ids need entropy, not luck
    type Sleep: Sleep;    // fn sleep(&self, ms) -> Timer; fn timer(&self, ms) -> Timer
    type Http: Http;      // fn send(&self, HttpRequest) -> Result<HttpResponse, HttpError>
    // fn sleep(&self) -> &Self::Sleep; fn http(&self) -> &Self::Http;
}

pub struct TodoServiceImpl<C: Caps> { caps: C }
impl<C: Caps> TodoService for TodoServiceImpl<C> { /* business logic */ }
```

- Core is `async` but runtime-free: it returns futures; hosts drive them
  (tokio native, JS event loop on wasm). No tokio dependency in core.
- Native host wires `NativeCaps` / `FileCaps` (`SystemClock`, in-memory or
  file store, `SystemRandom` over getrandom, `TokioSleep`, `ReqwestHttp`).
- Tests wire `TestCaps`: a virtual clock that moves only when code waits,
  in-memory store, deterministic `MockRandom` — which is what makes
  id-dependent behaviour reproducible rather than flaky — `MockSleep`, and
  `MockHttp` with scripted routes. `gabion::caps::timeout` bounds a wait on
  whichever clock the capability carries.
- Web host wires `WasmCaps` (mock clock/store/random/sleep/http). It exists to
  prove the wall compiles for wasm; the real `WebCaps` (js Date, IndexedDB, js
  crypto, `fetch`) lands with the thin-client pass.
- Storage v1: abstract `Store` trait; `FileStore` is the shipped native impl
  (pure Rust, no C deps keeps the single-binary promise). redb/sqlx left to the
  app.

## 7. Lint rulebook (Dune-style: ban the shortcut, not the person)

Each row: a shortcut an agent (or tired human) will take -> the mechanical block.

| Shortcut | Block |
|---|---|
| render imports any core | crate graph; unrepresentable (process wall) |
| feature A imports feature B's core/render | crate graph; unrepresentable (feature wall) |
| hand-edit Cargo.toml to sneak a forbidden dep | `gabion check` audits every Cargo.toml against the edge table |
| shared depends on a feature (upward leak) | same edge-table audit |
| tokio / std::fs / std::net / std::thread in any `*-core` | wasm build fails (these don't exist on wasm) |
| std::time in any `*-core` | compiles on wasm (panics at runtime!) — caught by `clippy::disallowed_types` deny in clippy.toml |
| effect without capability | same as above |
| DTO defined in core | render compile error at the wall |
| business logic in host crate | arch-lint: no type/fn definitions in hosts beyond wiring + main |
| forgetting to expose an op | the trait is the boundary: any method in a `#[service]` trait is on every surface, so there is nothing to forget |
| publishing an op by accident | `surface-snapshot`: `.gabion/surfaces.lock` must match the reachable method set |
| a `#[service]` trait declared outside `*-api` | `service-outside-api`: `#[service]` generates surfaces wherever it is written, so the lock scans every crate, and a trait in the wrong crate is named |
| hand-written HTTP handler bypassing contract | arch-lint: `axum` importable only in generated modules + host main |
| unwrap/expect/panic in core | `clippy::unwrap_used`, `expect_used`, `implicit_clone` deny |
| unsafe anywhere outside effects | `unsafe_code = "forbid"` workspace-wide |
| over-broad visibility (`pub` past the wall) | cargo-mend-style visibility check in CI [not built] |
| glob re-exports across the wall | clippy `wildcard_imports` deny on contract |
| code comments in service bodies (Dune's ban) | `no-comments-in-service-bodies` in `gabion check`: no comments inside `*-core` fn bodies; `///` docs on public items stay required (codegen needs them) |
| silent default on a failed read/write | `core-silent-default`: `unwrap_or_default()` / `unwrap_or(..)` on a `Result` in `*-core` is a finding — a corrupt row must fail loudly, not vanish |
| deleting the wall instead of fixing the code | `clippy-config`: `gabion check` audits `clippy.toml` itself; a removed ban or loosened threshold is a named finding |
| `#[allow]` smuggled into a pure crate | `allow-allowlist`: `clippy::disallowed_*` allows are legal only in a declared effect home |

Delivery (built): the gate is `gabion-cli`, run as `cargo run -p gabion-cli --
check`. It orchestrates `rustfmt`, `clippy` (workspace lints + `clippy.toml`),
`cargo test`, `cargo shear`, `cargo deny`, and a wasm build of every `*-core`,
then adds the rules above that need gabion's shape. The edge table is data in
`[workspace.metadata.gabion.edges]`, not code, so an app can widen its own walls
without patching the framework. CI template: `.forgejo/workflows/ci.yml`.
The point stands: `gabion check` green == architecture correct, so an agent with
zero context cannot pass CI while violating the wall.

Two deliberate deviations from the original plan:

- **No hand-rolled linter.** The first draft of this spec assumed a bespoke
  arch-lint. Only three rules turned out to need gabion-specific knowledge
  (edge table, surface completeness, effect-home allows); everything else is
  delegated to tools that already exist and are better maintained than we will
  be. Clippy's `too_many_branches` is the one exception: its threshold is
  hardcoded at 42, so the branch cap lives in `gabion check` instead.
- **Uniform thresholds across crate classes** (cognitive 15, lines 80, args 6,
  branches 10, type-complexity 150) rather than tiered limits per layer.

## 8. Verification story (verification > generation, per Tan)

- Core is pure -> deterministic unit tests with `MockCaps` (fixed clock, in-memory store).
- Generated conformance suite: the same `TodoServiceImpl` is driven through all
  four adapters (clap invocation, axum test request, rmcp tool call, in-proc
  client) and must agree on outputs. Agents prove work by execution, not review.
- `gabion check` = fmt + clippy + test + shear + deny + wasm-target build of
  core + the gabion-specific rules. One command, one exit code.
- The gate is dogfooded: `crates/gabion-cli/tests/dogfood.rs` runs the real
  checker over this repo, and `tests/rules.rs` proves each rule fires on a
  fixture that violates it. A rule without a failing fixture is the same trap
  as a README claiming a wall that isn't there.

## 9. Framework's own crates

```
gabion/         # runtime: prelude, client traits, error model, capability traits
gabion-macros/  # #[service] (#[GabionError] derive is not built yet)
gabion-native/  # native caps: SystemClock, FileStore (a declared effect home)
gabion-cli/     # `gabion check` (built); `gabion new`, `gabion dev` (not yet)
gabion-codegen/ # openapi export, contract snapshot (reviewable generated diff) [not built]
```

`gabion dev` runs server + wasm renderer + native CLI against one workspace with
one command — the agent loop stays fast, which is half of Dune's thesis.

## 10. Decisions

Signed off in the v0.1 audit:

1. **Per-call context is an explicit `Ctx` parameter** (principal, tenant,
   trace-id, cancellation) on every service fn, not a scoped service or a
   task-local. It is visible in the contract, trivially testable, and the
   generated adapters construct it. This deliberately breaks the "exactly one
   input argument" shape — accepted.
2. **Errors round-trip via a separate `WireError` plus `From`-style
   conversions.** Built. The in-proc error stays rich (thiserror-style typed
   detail); the wire type is flat and bidirectional, and `ErrorKind` is
   serialized instead of `#[serde(skip)]`. Conversions are generic runtime impls
   rather than per-service codegen.
3. **wasm browser posture: thin client over HTTP.** The render crate calls the
   generated HTTP client; core does not run in the browser. Local-first with
   IndexedDB/WebCaps is a later option, not the default.
4. **Dune's comment ban is adopted, scoped to `*-core` fn bodies.** Doc comments
   on public items stay required — codegen and OpenAPI read them.
5. **The trait is the boundary; there are no per-method surface attributes.**
   Every method in a `#[service]` trait is generated into every surface. Ops
   that must not be remote live outside the trait: a plain trait in `*-api` for
   cross-feature in-proc calls, inherent methods on the impl for
   feature-local internals. There is no opt-out for one surface — if it must not
   be remote, it is not in the trait. The reviewable artifact is the locked set
   of reachable ops (`.gabion/surfaces.lock`), not an annotation per method.

Still open (see `docs/GAPS.md` for the full log, ordered by how much damage the
silence does):

1. Renderer: agnostic + Dioxus template (recommended) vs bundled renderer stack.
2. Wire format: JSON-only v1 vs CBOR option.
3. Name (needs registry + SERP collision sweep before publishing).
4. Streaming surfaces: `Stream` return support — v1 or v2?
5. Whether `gabion check` should grow a `--fix` for the mechanical rules.

## 11. Cheapest experiments first

1. Spike the walls: hand-write two features (todo, billing) x api/core/render +
   one host. Prove: render cannot import core, todo-core cannot import
   billing-core, and the wasm build of a core fails on `std::time`.
2. Spike `#[service]` v0: macro that generates just the axum router + clap from
   the trait (skip mcp/client first). Prove one fn -> two surfaces compiles.
3. Add rmcp + Http client stub. Add `gabion check`. **Done:** `gabion check`
   exists, is tested against negative fixtures, and runs in CI; the rmcp and
   Http client stubs are not built.
4. Only then: `gabion new` scaffolding + Dioxus template.
